# 记背目录侧栏调整

用户明确要求在浏览正文任何位置都能看到侧栏式目录，并要求本轮不操控屏幕，由用户自行打开验收。每次改代码使用 frontend-design，在既有米白、苔绿与安静阅读风格内完善。

- 采用独立阅读工作区：顶部操作栏固定，正文在自身区域滚动，右侧目录另行滚动。拒绝继续在正文开头堆放目录，或让目录随长文离开视野。
- 内容区域宽度达到 800 像素时默认展示约 216 像素右栏；正文保持合理行宽。较窄时以固定“目录”按钮展开右侧浮层，不挤出不可读的正文窄列。点击章节后不自动关闭，可主动收起或按 Escape 返回正文。
- 正在阅读的章节采用浅苔绿底与左边标记，结合 aria-current；不加持续动效、提示标语、阅读进度奖励。长目录内部滚动，不改变正文位置。
- 顶部“目录”切换显隐，不再滚回开头。收起/展开、正文阅读位置在隐藏释放后恢复；窗口变宽变窄时不丢失正文位置。默认开合随宽度，用户手动选择优先。
- 继续沿用 knowledge.toc、Markdown 同源解析、安全锚点和现有事务/备份，不改数据库、安装器或更新器。
- 无标题给出简短提示，关闭每篇目录时正文占满工作区。旧笔记默认关闭。

后台验收：使用无可见窗口的 Chromium 加载真实本地页面和样式，受控桥接真实隔离 Store。检查宽窗/窄窗/短窗、滚动末尾目录仍可达、点击重复标题、当前章节、长目录独立滚动、键盘显隐、草稿与会话恢复、无标题、原文与备份保留。此证据不冒充本轮真实桌面/最小化/安装测试。

交付独立 D 盘预览包及快捷方式，只含虚构示例。用户亲自打开；不替换 0.5.3，不提交或发布，待本轮验收。

2026-11-22 验收结论：用户确认侧栏方案并验收通过，授权提交代码及发布 0.5.4。桌面版由用户自己更新；继续遵守不操作屏幕的边界。
